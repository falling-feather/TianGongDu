## 1. 暂停原因与定型边界

当前仓库已经积累了大量可运行原型、合同、测试、工具和内容蓝图，但这些成果回答得更多是“系统能否工作”，还没有充分回答“最终游戏为什么好玩、世界怎样长期承载这些玩法、哪些技术复杂度值得保留”。因此本轮收束把“继续加内容”从关键路径移除，把下一阶段定义为产品定型，而不是 `Demo 0.8.6` 功能冲刺。

### 1.1 仍然有效的产品支柱

《天工渡》仍是一款 2.5D 斜向全景动作与工艺经营角色扮演游戏。玩家是年轻的“执灯渡人”，在有人生活、生产、交易、争论和传承的东方工艺社会中，通过调查、交往、工艺、经营、探索与战斗让器物、工序、责任和关系重新归位。技艺必须成为可观察、可操作、可试用、可返工的玩法；经营必须改变材料、订单、关系和地区；战斗的终点不是清空敌人，而是处理失序并把结果带回社会与生产。

这些支柱是下一轮讨论的输入，不代表 04、05、07 中的每个系统、地区、角色数量、剧情结构或技术实现已经最终批准。

### 1.2 必须重新定型的三类问题

游戏设计需要明确目标玩家、核心循环、单次游玩结构、长期成长、失败与重试、战斗/工艺/经营的时间占比和相互因果，并判断现有 20–30 分钟江南闭环是否仍是最合适的验证单元。世界架构需要明确世界历史层级、天工院/工灯/工印/祟与“归位”的因果关系、地区之间的政治经济联系、现实工艺与幻想改写的边界，以及三地区是否仍是 1.0 的正确结构。技术栈复核需要回答浏览器首发、C++20/Axmol、Emscripten、Canvas/DOM 分工、同包双端、Workbench、内容包和本地优先存档是否与最终产品规模匹配，并以迁移成本和已有回归证据评估保留或替换。

### 1.3 本阶段不做

在上述三类决定完成前，不继续扩写剧情、新手引导、NPC 对话、敌人、Boss、工艺、订单、三地区内容、最终美术、移动端、云服务或商业化；也不进行引擎迁移、Schema 大改、编辑器扩张和历史代码瘦身。讨论可以产出草案、对比和 ADR，但未经用户确认不得写成已定型事实。

## 6. 恢复与验证节奏

### 6.1 恢复开发门

恢复产品写入必须同时满足：用户明确结束暂停；`PM-023`、`PM-024`、`ARCH-001` 至少完成到足以决定首个版本范围；`PM-025` 建立新的唯一任务顺序；根稳定基线和 Git/worktree 状态重新通过对账。未满足时只继续设计讨论和只读验证。

恢复后的默认流程仍是 Owner 自测 → 主开发 Review/集成 → 版本候选出现后按需召集 QA。普通任务不经过三个常驻工作组讨论；Schema、包格式、UI、资产和测试属于当前功能，只有独立真实阻塞时才拆前置任务。

### 6.2 人工与发布证据

稳定 0.8.5 只有实现者单 Edge 技术路线。非实现者 20–30 分钟试玩、传统工艺从业者/研究者审阅、Chrome/Firefox、Windows 可见窗口和五名目标玩家候选验收均保持 Open。恢复后每个玩家可见版本必须有截图或短录像，工艺/经营版本必须有非实现者试玩；只有合同、测试或命令行输出不能作为阶段成果。

### 6.3 自动验证

Owner 先运行受影响测试和一条真实人工路线，主开发 Review 后形成不可变候选，再按风险集中执行 Native、Web、浏览器、存档/回放和文档门。具体命令、环境与期望结果以 [`01-developer/16-测试CI与发布门禁.md`](01-developer/16-测试CI与发布门禁.md) 为准。

## 7. 系统型 Demo 放行条件

以下门保留为旧 `0.8.9` 候选的质量下限，不代表该版本仍按原计划执行。`PM-025` 可以在不削弱产品支柱、存档安全与人工证据的前提下重组版本，但不能把未完成项改名为完成。

### 7.1 玩家闭环

- 玩家能从 Web 首页进入，不依赖开发者命令或 QA 按钮。
- 首轮 20–30 分钟内完成地区需求、工艺/工坊取舍、路线变化、两波战斗和交付结果。
- 三名代表 NPC 各自承担不同系统功能，不以长对话填充时长。
- 工艺结果至少改变一个探索或战斗解法，探索/战斗结果至少回流一种材料、订单或地区反馈。

### 7.2 编辑器闭环

- 能新增、复制、删除并摆放六类基础对象。
- 能配置资源、波次、目标、工艺、订单和 terminal。
- 保存、加载、导出、Launch、修改和 Reload 成立。
- 重复 ID、缺资源、断路、不可达、图循环和坏引用有可定位诊断。

### 7.3 战斗与状态

- 两种战斗结构、必要技能、普通敌人职责与精英均可辨；具体数量由定型设计重新确认。
- 死亡、重试、离开返回和 reload 不重复推进、发奖或留下半状态。
- Windows/Web 使用同一内容和 Gameplay 真相，并能复核确定性输入。

### 7.4 表现与质量

- 灰盒候选可以存在，但 NPC、敌人职责、工位、材料状态、机关和攻击提示不能只靠颜色区分。
- Chrome、Edge、Firefox 与 Windows 通过适用门禁，520×800 与 200% 基本可用，键盘/手柄焦点不丢失。
- 至少 5 名目标玩家完成试玩，记录首个卡点、死亡、返工、重复感和实际分钟。
